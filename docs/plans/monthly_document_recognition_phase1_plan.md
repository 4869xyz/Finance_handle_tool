# 月度多资料识别第一阶段实施计划

## 目标

在保留现有单张发票 `/api/invoices/*` 流程的前提下，新增按员工、报销月份和目录批量登记、识别、查询及重处理的独立流程。第一阶段处理 `发票`、`补票`、`支付凭证` 三类来源目录，并对视频、重复汇总 PDF、超像素图片实行可审计的确定性短路。

## 已确认边界

- 实际根目录名称仅作上传载体，不解析员工或月份；两者来自表单。
- 缺少某个来源目录可视为该来源文件数为零；未知来源目录拒绝。
- 单文档最多 150 MiB、单批最多 256 MiB、最多 200 个文件。
- 视频只保存路径、大小、哈希等元数据，`file_data` 为空。
- 文件名只用于确定性特殊规则和弱分类，不能作为业务字段来源。
- 多笔独立交易且没有可信汇总金额时进入人工复核，公开金额为空，候选交易保留在 JSON 中。
- 第一阶段不处理根目录外的资金表格；版本号为 v0.4.0。

## 成功标准

- `example_file/马耿宾2025年3月报销发票` 可原子登记 91 个文档：3 个 `PDF合并.pdf` 跳过，1 个视频和 1 个超像素长图进入人工复核，其余进入识别队列。
- 批次、文档、来源、类型、处理状态、原因码、原始响应和结构化字段均可查询。
- 通用 PDF 文本层与图片 OCR 可服务多文档识别，模型响应经严格 Schema 校验；单文档失败不拖垮批次。
- 重处理只领取允许重试的人工复核/失败文档，特殊终态文件和处理中记录不重复领取。
- 旧 `/api/invoices/*` 行为及既有测试无回归。
- 前端 `/batches` 支持目录上传、统计、分页明细、轮询和中文原因展示。
- README、架构图、目录说明、工作流文档、版本日志和示例环境变量与实现一致。
